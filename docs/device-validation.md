## 0.2.0 新功能

| 功能 | 真机结果 |
|---|---|
| 默认背景 | 已检查浅色、深色显示；采用柔和渐变和圆形层次，修正透明 Scaffold 下的文字对比度 |
| 自选背景 | 小米通过系统图片选择器选择合成测试图；背景生效，强制结束并重启后仍保留 |
| 背景独立性 | 小米选择背景时，联想的背景不改变；两端分别保存，服务器不接收背景 |
| 恢复默认背景 | 小米恢复默认成功，本机 `background.bin` 已移除 |
| 自动归档 | 两台真机完成两轮共同记录，每轮结束后均自动保存双方图片并显示时间轴 |
| 首条记录动画 | 两端捕获到当天首条记录祝贺弹层；动画结束后出现第 1 条时间轴标记。最终包将祝贺文案分为两行居中显示 |
| 后续记录 | 两端均出现第 1、2 条标记，第 2 次只提示相应次数，未重复首条祝贺 |
| 标记详情 | 点击圆点进入详情，显示本次双方图片，支持放大及另存相册 |
| 历史持久化 | 联想强制结束、重启后仍可打开第 1 条记录；最终覆盖安装后两条记录均保留 |
| Google Material 3 日历 | 两端均可打开原生 Compose Material 3 DatePicker；选择 10 月 28 日显示空时间轴，选择 10 月 29 日可恢复已有记录 |
| 日期边界 | 单元测试覆盖 UTC 日历值转换、上海时区跨日、当天次数和删除后序号不回退 |
| 仅本机删除 | 在联想确认删除第 2 条测试记录，联想只剩第 1 条；小米仍保留第 1、2 条。已确认磁盘对应加密记录文件移除 |
| 本机加密文件 | 两端 `no_backup/journal` 只含 `index.bin`、`record-*.bin` 等私有加密文件，权限为仅应用用户读写；重启后可正常解密读取 |

结束测试时，联想保留 1 条、小米保留 2 条测试记录，这是“仅本机删除”测试的预期结果。历史存放在各自手机，删除不会同步到对方。

## 原有流程与修复回归

- 真实配对码输入、生成端确认、两端配对安全码核对通过。
- 联想发起 → 小米同意；小米发起 → 联想拒绝，两种方向均通过。
- 系统相机拍照、返回预览、截图取消与重新授权、单帧截图后停止投屏均验证；Android 16 的“共享整个屏幕”路径通过。
- 双方提交前不展示对方图片，提交后正确解密、显示。
- 两台手机相册保存的两张记录曾逐字节比对，SHA-256 相同；图库可打开保存的合成图片。
- 小米在用户开启持续接收服务、应用处于后台时收到真实好友邀请：通知 id 102 入栏；回到应用并同意后 id 102 清除。
- 小米当前勿扰模式值为 1；通知记录中存在系统视觉提醒抑制，因此不承诺本次测试会响铃或出现横幅。
- 已修复并回归：旧邀请通知残留、接收开关缺少无障碍标签、上一轮大图遮住新邀请。大图测试中，新邀请到达后旧预览关闭，可正常同意或拒绝。
- 覆盖升级 0.1.1 → 0.2.0 后，配对仍有效，两台互相显示在线。

早期单手机阶段使用的模拟好友已断开并关闭。后续主流程和新功能使用两台真实手机验证。

## 仍需后续覆盖

Android 8、Android 17 对应真机；长时间锁屏/深度省电、进程被系统终止后的送达；横屏、分屏和大字体矩阵。当前不包含厂商离线推送或外网入口。

0.2.0 以前的临时记录没有自动迁移进时间轴。新历史仅在本机加密保存；清除应用数据或卸载会失去本机历史，服务器无法恢复。
