# 0.4.0 双机验证补充

日期：2026-10-30。安装包与已发布的 0.4.0 完全一致，versionCode 6；本轮未修改应用代码或重新发布 APK。

设备：联想 L79031 / Android 11（USB ADB），小米 23127PN0CC / Android 16（无线 ADB）。两端从 0.3.1 覆盖升级；测试结束保留两端的配对与本机历史。

## 已完成

- 两台手机均显示新版协议和首次权限引导。通知入口可操作，完成引导后进入应用，没有提前申请相机、截图或相册保存权限。设备已有通知授权，本轮不代表全新安装的权限拒绝分支验证。
- 联想生成配对码，长按后将剪贴板内容粘贴到输入框，确认与原始 8 位数字一致；复制好友口令按钮可操作。
- 小米前台识别带 SHARETIME 标记的剪贴板口令，出现“发现好友口令”，确认后联想收到配对申请，联想同意后双方恢复配对，安全码与原来一致。口令文本通过系统输入框写入剪贴板来模拟好友复制场景，没有向第三方联系人发送消息。
- 联想保持接收服务在后台运行，收到小米邀请时，出现无按钮的小条提醒；截图确认随后消失。系统 HIGH 邀请通知也正常存在。沿用既有悬浮窗授权；没有更改设备的勿扰模式。
- 联想点击拍照后打开系统相机，返回可继续记录；小米点击截屏后才出现系统投屏授权，取消后正常返回。联想系统截屏授权后得到一张预览，随后提交成功。
- 云端双机记录：小米选择合成测试图片并提交；联想提交应用页面的截屏。双方完成后均出现当天首次完成动画，时间轴新增 2026-10-30 09:43 的标记，点击可看到双方内容。
- 两台手机设置中的“检查更新”可用；与服务器当前同为 0.4.0，不出现虚假的升级提示。此前已验证公网版本清单和 APK 下载后的散列、大小一致。
- 测试结束双方保持配对，应用返回主页。没有清除应用数据或删除历史；只读统计时两端分别有 4、5 个加密记录文件（两端历史本来不同）。

## 限制与未覆盖项

- 联想 USB 在最后提交前短暂断开，用户重新连接后继续，已完成本轮记录。
- 联想系统文件选择器本轮点击图片未返回选择结果，因此改用系统截屏完成记录；不能据此宣称联想选图路径已通过。小米系统选图返回及提交正常。
- 本轮未发布虚假高版本来强制触发升级。更高版本提示、浏览器下载与系统覆盖安装的完整手机流程，留待下一次实际发版验证。当前手机中的版本与云端最新版相同。
- 未覆盖全新安装的通知拒绝、悬浮窗新授权、长时间待机与开机恢复，以及 Android 8、17 真机。

原始 UI 截图、通知记录和界面树保留在开发电脑本地；照片选择器与设置搜索页面的截图已清理，不上传公开仓库。
