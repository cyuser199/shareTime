# 双人模式与好友模式（0.7.0）

以下为 0.7.0 的实现记录；当前 0.7.2 已改为发起后立即准备图片、首次提交锁定名单，详见 [0.7.2 流程](friend-layout-0.7.2.md)。

进入应用时选择模式，默认双人模式。设置顶部可以再次切换。两种模式保留独立关系及时间轴，双人配对不会因创建群组而解除；当前连接监听所选择模式的邀请。进行中的记录需结束后才能切换。

好友模式最多 5 人，包含创建者。创建好友群组后分享 8 位群组码，其他成员在好友模式加入。可离线加入已存在的群组；邀请代码 3 天有效，可由群内成员更新，旧码随即失效。退出仅移除自己，最后一人退出后删除群组，不删除本机历史。

记录流程：

1. 至少两位成员处于好友模式并在线，由一人发起邀请。
2. 邀请只发给当时在线的群成员，等待加入最多 5 分钟，成员自行选择参加或拒绝。
3. 至少两人同意并在线后，发起人点击“开始本轮”，锁定参与名单。未加入、拒绝、离线成员不阻塞开始；开始后新成员不能读取本轮内容。
4. 锁定的参与者在 10 分钟内拍照或截图并提交，全部提交后才能查看彼此记录。开始后参与者离开群组会结束本轮，单纯断网可重连继续，超时则结束。
5. 每张图片为每个收件人分别使用现有 P-256/HKDF/AES-GCM 加密，服务器只转发各自密文。记录及成员标签加密保存在本机，详情按竖向展示所有参与者图片。

服务器新增 `groups.json`，只保存群组标识、成员昵称/设备标识/公钥、邀请码和期限，用于跨重启恢复成员关系。成员退出时删除其群组成员信息，最后一人退出后删除群组；过期邀请码清理。图片、参与名单和进行中的记录仅保存在有上限的内存，确认接收、超时、取消或服务重启后清理。新版协议 v4 已说明新增保存范围。

验证：服务端 19 项测试通过，涵盖 5 人上限、过期码、重启恢复、局部参与、名单锁定、收件人隔离、清理及独立双人配对。云端 5 个合成客户端完成完整群组协议流程，确认每端只收到其他四人的指定副本，测试群组已删除。客户端新增 5 人逐个收件人加解密与错误收件人认证失败测试。

联想 Android 11 与 Android 9 模拟器已验证模式选择、创建/加入、同意与开始、实际图片加密交换与本机保存，以及切回双人模式后原配对、历史和在线状态保留。五台物理手机同时操作尚未验证。
